# quick-context.md — read this first

High-signal context for agents picking up this repo. Last verified on the
physical TV: **2026-11-03**. Full detail lives in `PROLEWEBOS.md`; procedures
in `RUNBOOK.md`.

## What this repo is

- **prole-webos** — a sideloaded webOS app (`com.fdear.prolewebos`, v1.4.0)
  that acts as a quiet home screen: clock, rotating wallpapers, configurable
  dock, All apps / Inputs / Settings overlays.
- **Debloat toolkit** — backs up and reversibly changes 11 TV settings, plus a
  DNS blocklist. Nothing is rooted.
- Public GitHub repo: `fdearaujosiles/prole-webos` (remote `origin`).

## Hard rules

1. **G30 — always ask before pushing.** When finished and verified, ask the
   user whether to push and whether the target is `main` or a new branch. Wait
   for the answer. Never push, force-push or open a PR unprompted.
2. **Non-root only.** No rooting, no system-partition writes, no unsupported
   hacks. Treat the TV as a shared device.
3. **No TV app uninstalls** except prole-webos, and only after the user agrees.
4. **Never print secrets** (SSAP client key, GitHub token).

## Commands

```bash
bash scripts/connect.sh          # register ares device "tv"
bash scripts/backup.sh           # back up prefs + app list first
python scripts/debloat.py        # apply reversible changes
bash scripts/restore.sh          # undo debloat from backup
bash scripts/package-install.sh  # build IPK, install, launch, screenshot
npm test                         # selftest against local fixture (no TV)
```

Build only: `node node_modules/@webos-tools/cli/bin/ares-package.js app -o packages`.

## App architecture facts

- App id and service id both use `com.fdear.prolewebos`; keep them stable.
  Renaming installs a **new app** and loses localStorage (dock, SSAP pairing).
- localStorage keys: `prolewebos.dock`, `prolewebos.ssapKey`.
- Catalog loads **once at boot** via the Luna service
  (`luna://com.fdear.prolewebos.service` → `com.webos.applicationManager/listLaunchPoints`).
  Fallback is `KNOWN_APPS`, probed with `luna getAppLoadStatus`.
  Newly installed/unhidden apps need a relaunch to appear.
- Filters out `hidden === true`, the app itself, and input launch points;
  dedupes on `launchPointId`; adds Settings; sorts by title.
- Dock: max 10 pins, 8 defaults (7 streaming + RetroArch). Persisted in
  `localStorage['prolewebos.dock']`, repaired by title when IDs drift.
- Deliberately legacy: `window.AURORA_WALLPAPERS` and the wallpaper scene
  named "Aurora" are artwork data; `window.AURORA_CONFIG` is a compat fallback.
  Do not "fix" these unless the user asks.
- `probe/` is an unrelated research app ("Aurora Probe"); leave it alone.

## Verification gotchas (learned the hard way)

- **`ares-package` minifies JS.** Installed `service.js` and page JS never
  byte-match source (e.g. service.js 5,534 → 2,670 bytes). Compare build
  output, not installed files, unless proving deploy.
- **`ares-launch` may focus a stale instance.** After reinstalling, the DOM can
  show an old catalog. Force `location.reload()` over CDP before trusting it.
- **CDP proxy port changes.** `ares-inspect -d tv -a com.fdear.prolewebos`
  prints the current port and must stay running; `backup/.inspector-port` can
  be stale. Confirm with `curl http://127.0.0.1:<port>/json`.
- **Bash tool:** long commands auto-background; don't chain a bare `sleep`
  before other commands — wait inside a CDP expression instead.
- **`ares-shell` is unsupported** on the `tv` profile. Use `scripts/tv.sh`
  (`ares-novacom --run`) for reads; `luna-send` over novacom is Permission
  denied.
- Images cannot be visually inspected in every model. Verify splash branding
  by reading `scripts/gen-assets.py` (`draw.text(..., "prole-webos", ...)`)
  and matching md5s: splash `8dfca385896d9f1f29dce4bc9a2beacb`,
  icon `1048c070132e4e487cc0625ab3f3b720`.
